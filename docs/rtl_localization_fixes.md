# دليل توثيق التعريب وإصلاحات الاتجاه (RTL Docs)
**تاريخ التوثيق:** أبريل 2026

هذا الملف يوثق كافة الملاحظات، المشاكل، والخطوات التقنية التي تم اتخاذها لحل أزمة التعريب وتداخل عناصر الواجهة (RTL Layout) في لوحة تحكم Larkon.

---

## 1. مشكلة التعريب الثابت (Hardcoded Localization)
**الملاحظة:** كانت العديد من المكونات في `index.blade.php`, و `topbar.blade.php`, و `main-nav.blade.php` تحتوي على نصوص إنجليزية ثابتة وتفتقد لدعم اللغة المحملة.
**الخطوات التي تم تنفيذها:**
- تم بناء قاموسين للترجمة في مجلد اللغات `lang/ar/messages.php` و `lang/en/messages.php`.
- دمجنا مفاتيح الترجمة ديناميكياً باستخدام مساعد لارافل للترجمة `{{ __('messages.key') }}`.
- تمت ترجمة القائمة الجانبية (Sidebar) كاملة، وأيضاً بطاقات إحصائيات لوحة القيادة، والجداول السفلية، وشارات الحالة (Processing, Completed).

---

## 2. مشكلة انعكاس الأرقام والنسب (Bidirectional Text Issue)
**الملاحظة:** عند التبديل للغة العربية `dir="rtl"`، الأرقام التي تحتوي على فراغات مثل `13, 647` كانت تنعكس تلقائياً إلى اليمين لتظهر `647 ,13`، مما أفسد المظهر المالي والإحصائي.
**الخطوات التي تم تنفيذها:**
- تم تنظيف الأرقام بإزالة الفراغات المسببة للانعكاس `13,647` بدلاً من `13, 647`.
- تم استخدام وسم `<bdi>` (Bi-Directional Isolation) حول المبالغ المالية مثل `<bdi>$123.6k</bdi>` ليجبر المتصفح على قراءتها ككتلة واحدة بغض النظر عن اتجاه الصفحة العامة.

---

## 3. المعضلة الكبرى: تداخل المحتوى مع القائمة (Layout Overlaps in .page-content & .main-nav)
**الملاحظة الرئيسية التي لاحظها المستخدم:** منطقة `page-content` كانت تنزلق لتصبح *تحت* وتمتد خلف `main-nav` الجانبية، مما يشوه الواجهة ويقص أجزاء من الرسوم البيانية وتصاميم الـ Topbar. والسبب أن ملف الـ Bootstrap والـ CSS الأساسي (LTR) يثبّت إزاحة المحتوى من اليسار `margin-left: 260px;` ولا يقوم بعكسها في الوضع العربي.

**المحاولات والحلول:**
1. **الحل الأول (Automated PostCSS):** 
   - تم إعداد `postcss.config.js` مع مكتبة `postcss-rtlcss` لعكس الـ CSS بشكل آلي أثناء عمل الـ Build.
   - **النتيجة:** توقف هذا المسار بسبب توقف أوامر الـ Docker داخل بيئة الجهاز الأساسي (Container not running)، واستحالة تشغيل `npm run build`.

2. **الحل النهائي والعملي (Direct Blade Custom Styling - Bypassing Build):**
   - تم حقن كود `CSS` قوي ومخصص داخل الملف الهيكلي `resources/views/layouts/vertical.blade.php`.
   - يتم تفعيل هذا الكود **فقط** إذا اختار المستخدم اللغة العربية: `@if(app()->getLocale() == 'ar')`.
   - **ما قام به هذا الكود:**
     - ألغى `margin-left` للمحتوى وأجبره على استخدام `margin-right: 260px` في وضع سطح المكتب الطبيعي.
     - صحح اتجاهات الإزاحة التلقائية لحالات القائمة المخفية والشاشات الصغيرة (`condensed`, `sm-hover`, `hidden`).
     - صحح اتجاه أيقونة البحث ونافذة الـ profile وأرقام الإشعارات بـ `topbar-badge`.

---

## 4. الملاحظات المستقبلية (Future Recommendations)
1. **تعديلات الألوان أو الستايل:** إذا توفرت بيئة Docker وكانت حاوية التطبيق `perfume_admin-laravel.test-1` تعمل، يمكنك حينها تشغيل الأوامر التالية بأمان لترجمة الـ SCSS الأصلي دون الحاجة للـ Inject:
    ```bash
    docker exec perfume_admin-laravel.test-1 npm install postcss-rtlcss autoprefixer --save-dev
    docker exec perfume_admin-laravel.test-1 npm run build
    ```
2. **إضافة عناصر جديدة للـ Blade:** دائماً تأكد من التغليف للترجمة `{{}}` لضمان ديناميكية التحول.
3. **مكتبة ApexCharts:** حالياً الرسوم البيانية تعمل من اليسار لليمين LTR (لكي تحافظ على منطق تسلسل الأرقام والأشهر الزمني في عرض البيانات). تم تغليف وعاء الرسم البياني بـ `<div dir="ltr">` قصداً حتى لا تنعكس محاور السينات وتتداخل بشكل سيء.
